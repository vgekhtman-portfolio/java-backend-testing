# tests/contract

Consumer-driven contract testing of the orders REST API with Pact-JVM. REST only.

## How it works

1. **Consumer side** (`consumer/OrdersConsumerPactTest`): a hypothetical `orders-client` declares what it
   expects from the `orders-service` for `POST /orders` and `GET /orders/{id}` (including the 404 case),
   exercises its own client code against Pact's mock server, and writes the resulting pact file to
   `tests/contract/build/pacts/`. Values that vary per call (the id, timestamp and payment outcome of a
   created order) use matchers; values under the test's control are exact.
2. **Provider side** (`provider/OrdersProviderVerificationTest`): replays that pact file against the real,
   running orders-service (started by the shared Testcontainers extension) — a verification of live
   behaviour, not a mock.

The two run in order within a single test task (`@Order` plus a class orderer in
`junit-platform.properties`), and the task clears the pact directory first, so the provider always verifies a
pact generated by the same run.

## Provider states backed by the database

`GET /orders/{id}` only has something to return if the order exists. Before each such interaction the
verification applies the interaction's provider state (`an order exists` / `no order exists`) by writing to,
or deleting from, the service's Postgres directly. This is why the contract tests need a provider you own,
including its database.

## Verification is sensitive to breaking changes

Renaming a response field in the service (`status` → `state`) makes the verification fail with
`Actual map is missing the following keys: status` for the interactions that include it, while the 404
interaction, which doesn't, still passes.

## Scope

- REST only. Pact also has a plugin ecosystem for gRPC contracts, which is not covered here.
- Pacts are generated and verified locally; no Pact Broker is used. A broker would be the natural next step
  for sharing pacts between separately deployed consumer and provider pipelines.

Every test is tagged `@Tag("custom-sut")`.
